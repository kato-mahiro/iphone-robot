# iPhoneを利用したコミュニケーションロボット プロジェクト概要

## 1. プロジェクトの目的

3週間後に開催される生成AI関連の展示会に、来場者と実際に会話できる据え置き型コミュニケーションロボットを出展する。

使っていないiPhone SE（第2世代）をロボットの顔および入出力装置として再利用し、短い開発期間でも応答が速く、安定した会話体験を成立させる。多機能化や複雑な機構よりも、来場者が迷わず話しかけられ、キャラクターから自然に返答されることを優先する。

## 2. 開発条件と制約

- 展示会までの期間は約3週間。
- 作業時間は1日最大2時間で、理論上の総作業時間は最大約42時間。
- ロボットを移動させる必要はなく、据え置き型とする。
- iPhone用のネイティブアプリは原則として開発せず、Safariで動くWebアプリを使用する。
- 開発・推論用PCにはMacBook Air M2を使用する。
- 会場のネットワークは帯域やポート設定に制約があるため、機器間通信には使用しない。
- iPhoneとMacの接続には持参するWi-Fiルーターを使用する。
- Lightningケーブルは原則としてiPhoneへの給電に使用する。
- クラウドAPIの利用は許容する。
- 音声合成の声やサービスには、現時点で強い指定はない。
- CAD経験は浅いため、外装設計はCodex、Fusion 360 MCP、コードCADなどを活用して進める。

## 3. 最小完成条件（MVP）

展示時に、次の一連の体験が安定して動作することを最小完成条件とする。

1. 来場者がiPhone画面上のボタンを押して話す。
2. iPhoneのマイクで音声を取得し、Macへ送信する。
3. Mac上で音声を日本語テキストへ変換する。
4. キャラクターの性格や記憶を考慮して返答文を生成する。
5. 返答文を合成音声へ変換する。
6. iPhoneのスピーカーから返答を再生する。
7. 発話状態に合わせて、iPhone画面上の目などを変化させる。

会話開始方式は、常時待受やウェイクワードではなく「押して話す」方式から実装する。

## 4. ハードウェア構成

### iPhone SE（第2世代）

- ロボットの顔となるディスプレイ
- タッチ式の会話開始ボタン
- 来場者の音声を取得するマイク
- 合成音声を再生するスピーカー
- 将来の画像認識などに利用できるカメラ

### MacBook Air M2

- iPhone向けWebアプリの配信
- Hayamimiによるローカル音声認識
- 会話エージェントの実行
- キャラクター設定と会話記憶の管理
- クラウド上のLLMおよび音声合成APIとの通信

### 持参Wi-Fiルーター

- iPhoneとMacBook Airのローカルネットワークを構成する。
- 会場ネットワークから独立した機器間通信を提供する。
- クラウドAPIを使用するためのインターネット接続にも利用する。

### 3Dプリント外装

- iPhoneを安定して立てられるスタンドまたはケースを作る。
- iPhone全体を単に露出させず、ロボットらしいカバーを被せる。
- 目、ハート、会話ボタン、状態インジケータなど、インタラクションに必要な画面部分だけを開口部から見せる。
- マイク、スピーカー、カメラ、充電端子を塞がない構造にする。
- 展示中に倒れにくする

## 5. ソフトウェア構成

```text
iPhone Safari上のWebアプリ
  ├─ 押して話すUI
  ├─ マイク音声取得
  ├─ 目・口などの表情表示
  └─ 合成音声の再生
             │
             │ HTTPS / WSS（持参ルーター内）
             ▼
MacBook Air M2
  ├─ HTTPS/WSSサーバー
  ├─ Hayamimi（ローカル音声認識）
  ├─ 会話制御
  ├─ piまたはCodex系エージェント
  ├─ キャラクター設定・記憶
  ├─ クラウドLLM API
  └─ クラウド音声合成API
```

ブラウザからマイクを利用するにはセキュアな接続が必要なため、MacからWebアプリをHTTPSで配信し、音声はWSS（暗号化されたWebSocket）で送る。CaddyなどをTLS終端およびリバースプロキシとして利用する構成を想定する。

## 6. 音声認識

音声認識には、オープンソースプロジェクトの[Hayamimi（早耳）](https://github.com/oboroge0/hayamimi)を第一候補として使用する。

HayamimiはCPUだけで動くリアルタイム多言語音声認識システムで、量子化ONNXモデルとsherpa-onnxを使用する。`--input ws`によってスマートフォンからWebSocket経由で音声を受け付け、認識途中および確定後のテキストをJSONイベントとして返せるため、本プロジェクトとの適合性が高い。

日本語と英語のみの `--minimal` 構成を基本候補とする。iPhone側では、マイク音声をHayamimiが受け取れる16kHz・モノラル・PCM signed 16-bit little-endian形式へ変換して送信する。

押している間に音声を送り、ボタンを離した後に短い無音区間を送ることで、HayamimiのVAD（音声区間検出）に発話終了を認識させる。確定したテキストを会話エージェントへ渡す。

## 7. 会話エージェントと記憶

会話のバックエンドには、piまたはCodex系のコーディングエージェントを利用する方針とする。具体的な実行基盤は未決定だが、次の役割を持たせる。

- キャラクターの性格や口調に沿った返答生成
- 来場者との過去の会話や出来事の記憶
- 必要に応じたツール実行
- iPhoneへ返す発話文と表情指示の生成

たとえば、返答を次のような構造化データにする。

```json
{
  "speech": "こんにちは。今日は何を見に来たの？",
  "expression": "happy",
  "memory": "来場者はロボット展示に興味がある"
}
```

キャラクター設定、記憶形式、LLMサービスは交換可能な層として設計し、音声認識やiPhone画面と密結合させない。

## 8. 音声合成と画面表現

返答文の音声合成にはクラウドAPIを利用する。サービスおよび声は現時点では未決定であり、応答速度、日本語の自然さ、導入の容易さを見て選択する。

iPhone画面には、少なくとも次の状態を用意する。

- 待機中
- 聞き取り中
- 考え中
- 発話中
- エラーまたは再試行

表情は目や口などの単純なHTML/CSSまたはSVGアニメーションで構成する。発話中は音声の再生状態に合わせて口を動かす。高度なリップシンクはMVPには含めない。

## 9. 外装・CADの方針

外装はFusion 360だけをMCPで逐次操作する方法に限定せず、build123dまたはCadQueryによるコードベースの設計も候補とする。

寸法や形状をPythonコードでパラメトリックに定義し、STEP形式で出力してFusion 360へ読み込む。Fusion 360では、部品の配置、結合、追加の穴加工、手作業による仕上げなどを行う。

STEPでは正確なB-Rep形状を受け渡せるが、Pythonコード側の変数や作成履歴はFusion 360へ引き継がれない。設計履歴の本体はPythonコードとして保持し、形状変更時にはSTEPを再出力する。3Dプリント直前にSTLまたは3MFへ変換する。

### 現在のケース試作（V1）

白PLA用の「スタンド一体ホルダー＋前面カバー」をFusionの履歴・寸法パラメータ付きで作成した。編集用原本は `cad/phone-robot-case-v1.f3d`。部品別のSTEP・造形姿勢のSTLも `cad/` にある。

寸法、変更方法、組み立て・印刷上の注意、未検証事項は [ケースV1の設計メモ](docs/robot-case-v1.md) を参照。**各穴の寸法・種類・役割と、画面左上基準の配置は [開口部の寸法・配置仕様](docs/robot-case-v1-openings.md)** にまとめている。既存のFusion参照モデル名はSE第3世代のため、SE第2世代実機への装着は別途確認する。

## 10. MVPに含めない機能

次の機能は、会話体験が安定して完成した後、時間に余裕がある場合のみ追加する。

- 車輪やサーボによる移動
- 自律走行、地図作成、障害物回避
- 常時音声認識やウェイクワード
- 高度な人物認識や来場者の自動追跡
- カメラを使った複雑な画像理解
- 精密なリップシンク
- 複数話者の高度な識別
- 複雑な物理ボタン、LED、追加センサー

カメラは将来利用できるよう外装で塞がないが、MVPの必須機能とはしない。

## 11. 技術上のリスク

### HayamimiのmacOS対応

HayamimiはWindows 11で開発・検証されている。使用技術はクロスプラットフォームだが、macOSでの一連の動作は公式には未検証である。M2 MacBook Airで、依存関係の導入、モデルの読み込み、日本語認識、WebSocket入力が正常に動くかを最初に確認する。

動作しない場合に備え、音声認識部分をクラウドSTT APIへ交換できる境界を設ける。

### iPhone Safariの制約

- マイク利用には原則としてHTTPSが必要。
- 音声再生はユーザー操作を起点に許可されるよう設計する。
- Web Audio APIからHayamimi用PCMへの変換を実装する必要がある。
- 画面ロック、Safariのバックグラウンド化、省電力設定によって動作が停止しないよう、展示前に端末設定を確認する。

### ネットワークとクラウド依存

iPhoneとMac間の音声認識はローカルで完結するが、LLMと音声合成はインターネット接続に依存する。通信が一時的に失敗した場合のタイムアウト、再試行、画面表示を用意する。

### 展示環境の騒音

展示会場では周囲の会話やスピーカー音が入りやすい。押して話す方式によって入力区間を限定し、実会場に近い騒音下で認識テストを行う。必要ならiPhoneへ口を近づけることが自然に伝わる外装または画面案内を採用する。

## 12. 最初に行う技術検証

本格実装前に、次の順で最小の縦断動作を確認する。

1. M2 MacBook AirでHayamimiをインストールする。
2. Mac内蔵マイクから日本語をリアルタイム認識できることを確認する。
3. Hayamimiを `--input ws` で起動し、テスト音声をWebSocketで送る。
4. iPhoneとMacを持参ルーターへ接続し、iPhone SafariからMacへ到達できることを確認する。
5. HTTPS/WSS環境で、iPhoneのマイク音声をHayamimiへ送信する。
6. 確定テキストを仮のLLMへ渡し、返答文を得る。
7. 音声合成した返答をiPhoneで再生する。

この縦断動作が成立した段階で、キャラクター、記憶、表情、外装を順次追加する。

## 13. 現時点の未決定事項

- キャラクターの名前、性格、口調、外見
- piとCodex系エージェントのどちらを主に使うか
- 使用するクラウドLLMと音声合成サービス
- 記憶の保存形式と、来場者ごとの識別方法
- iPhone用Web画面の具体的なデザイン
- 3Dプリント外装の形状、寸法、素材、固定方法
- 時間が余った場合のカメラ利用方法

これらは基本構成を変更せず後から決められるため、開発開始を妨げる事項ではない。

## 14. 完成方針

本プロジェクトでは、ロボットの機構的な複雑さではなく、会話の応答速度、キャラクターらしさ、展示中の安定性を完成度の中心とする。

まず「押して話すと、すぐにキャラクターとして音声で返答する」という一本の体験を完成させる。その後に記憶、表情、外装、カメラなどを加え、途中段階でも展示可能な状態を維持しながら開発する。

## 15. iPhone用Web画面（実装済み）

`web/` に、押している間のマイク音声をHayamimiへ送る最小のSafari画面を用意している。
音声はブラウザ側でモノラル16kHz・PCM signed 16-bit little-endianへ変換し、
`/ingest` のWebSocketへ送信する。Hayamimiから返るpartial/final/refineイベントは画面に表示する。

Macで静的ページを配信するには、プロジェクトルートから次を実行する。

```bash
python3 scripts/serve_robot_web.py --host 0.0.0.0 --port 8080
```

Hayamimiは別ターミナルでLAN接続を許可して起動する。

```bash
cd hayamimi
.venv/bin/python scripts/realtime_transcribe.py --input ws --ws-host 0.0.0.0 --serve --lang ja
```

Safariでは `http://<MacのIPアドレス>:8080/` を開く。iPhoneのマイク利用にはHTTPSが必要なため、
実機テストや展示ではCaddyなどでWeb画面をHTTPS配信し、WebSocketもWSSで中継する。
接続先は画面下部の「接続設定」から変更できる。
